# SourceNest 2.1

SourceNest keeps your registered projects, notes, transcripts and provider settings while upgrading the managed files. Use Python 3.11+ and the verified SourceNest release ZIP. The package updater previews changes with `update --check` and can restore the previous managed package with `rollback`. It stops on modified managed files so you can review them individually.

Use `python beyin.py --root VAULT workspaces` to list project IDs. Unless noted otherwise, commands below take `--project ID` or the exact visible project name.

| Command | What it does |
| --- | --- |
| `context "topic" --json --limit 3 --budget 2400` | Finds passages around the query and returns the original note path and byte hash. The budget counts note text in characters. |
| `selftest --file cases.json --limit 3 --budget 2400` | Checks query, source and expected quote triples and exits nonzero on a miss. Uses no model. |
| `note-read --source notes/topic.md` | Reads a human Markdown note and its byte hash. |
| `note-edit --file edit.json` | Replaces a note body only when its current SHA matches the requested revision. Retains the previous bytes and the SourceNest metadata. |
| `history --source notes/topic.md` | Reads checksummed note revisions. |
| `checkpoint --file handoff.json` | Saves one card per session with open threads, next step, source references and an optional learning candidate. Use `--dry-run` for a preview. |
| `recap --days 7` | Lists recent handoffs and closed tasks with source references. These are assertions recorded by the session. |
| `task-create`, `task-update`, `tasks` | Manage explicit projects tasks with stable IDs and revision checks. States are open, blocked, done and cancelled. |
| `learn`, `learn-resolve` | Inspect and resolve learning candidates. Accepting a candidate records the review result. To publish an authoritative note, use `note-create` with its evidence. |
| `feedback --file feedback.json` | Attaches ok, wrong or stale feedback to a note revision. Wrong and stale revisions are excluded from context until the source changes or the feedback is revised. |
| `triage`, `lint`, `moc`, `homepage-create` | Report stale tasks, capture notes, candidate decision changes, duplicate titles, broken links and orphans. Create a project-scoped links page. |
| `capture --file item.json` | Saves an explicit private text or URL capture for local evaluation. No URL content is fetched. |
| `backfill --adapter codex --file session.jsonl` | Previews one selected export. Repeat with `--approve-sha HASH` to archive the previewed user/assistant text as private notes. The import stays out of hooks and the model queue. |
| `scheduled-check` | Refreshes the selected project's views and reports local diagnostics. You provide any scheduler. |
| `devices --detect` | Reports the local configuration. `devices --plan --level phone --phone-sync obsidian` plans phone access. Use `--apply` in place of `--plan` to record the selection locally. SourceNest does not configure a sync vendor. |
| `web` | Starts an authenticated browser screen on 127.0.0.1. Open the single-use link printed by the command. Search notes or save a private capture. Close the process to stop the screen. |
| `clients plan --client pi --workspace FOLDER` | Previews the Pi extension and shared instructions. The registered workspace controls scope. Replace `plan` with `install` to apply reviewed changes. |

Type the input in JSON. For example:

```json
{"session":"session-id","title":"Release notes","outcome":"Kept the existing update path","next_step":"Check installation","threads":["Verify the next session"],"refs":["notes/release.md"]}
```

A retrieval test file contains an array:

```json
[{"query":"release path","source":"notes/release.md","expected":"update path"}]
```

Note edits accept `source`, `sha256` and `body`. Feedback accepts `source`, `sha256`, `verdict`, `reason` and optional `session`. Task creation accepts `id`, `title`, `next_step`, optional `status`, `due` and `refs`. Updates require `id` and the current `revision`. Capture takes `title`, `body` and an optional `url`.

Project-scoped rules can live at `notes/project-rules.md`. The assistant treats handoffs and note text as historical source context. Maintain these notes alongside the project's active instructions.

Pi's project extension uses prompt capture and lifecycle context. It does not read an entire Pi transcript. Global hook repair operates separately from vault updates. Jev and Laya use the existing provider controls and require explicit configuration. Private archive notes are never sent to the advisor or injected into automatic context.

Adaptation reference: [AvenoxBeyin 3.15.0](https://github.com/avenoxai/avenoxbeyin/releases/tag/v3.15.0).

Use `hook-reconcile --client codex --file SETTINGS --old-root PREVIOUS_VAULT --old-python PREVIOUS_PYTHON` to preview repair of exact stale SourceNest entries. Add `--apply` to commit the result with a byte-for-byte backup. Review client trust after a repair.
